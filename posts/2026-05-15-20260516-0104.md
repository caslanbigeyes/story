### 2. I love Linux, but I can't quit Windows

- 文章来源平台：Hacker News
- 原文链接：<https://news.ycombinator.com/item?id=48150414>
- 热度/摘要：13 points

**AI 总结**

- Linux 本身系统质量过硬，但关键商业软件（如 IntelliJ 的键位绑定冲突、部分企业级应用）对 Linux 桌面支持不足，导致用户被迫留在 Windows。  
- Windows 存在大量“玄学”问题（如 SSD 开机慢、蓝屏、驱动冲突），且通常难以自行修复；而 Linux 的类似问题往往有明确可查的解决方案，但需要一定技术背景。  
- 硬件兼容性差异明显：同一台电脑上 Linux 可稳定运行，Windows 却出现频繁浏览器崩溃或睡眠唤醒异常，说明 Linux 在特定场景下的稳定性反而更具优势。  
- 用户在 Windows 下的痛点（如任务栏无法调整、睡眠不可靠）虽然烦人，但大多“可忽略”或靠第三方工具缓解；而 Linux 下的痛点（如更新后系统故障）往往是“阻塞性”的，直接导致无法正常使用。  
- 结论：Linux 桌面生态在软件支持、用户友好度上仍有明显短板，尽管系统本身更可定制和可控，但许多用户因无法替代的 Windows 专属软件或 IT 环境而无法彻底切换。

- 热度/摘要：13 points

- 评论指出，Wharton研究中使用的AI能力图纵轴定义模糊（如“人类完成任务的工时”），可能导致对模型能力跃升的过度解读，比如Opus 4.6是否真的比GPT 5.1 Max强一倍以上存疑。
- 多位参与者认同“指数终将变成S形”是普遍规律，但当前阶段仍可能处于指数增长区间，过早断言饱和会低估进步；也有观点称该文章自身论点前后矛盾，被批评为点击诱饵。
- 讨论延伸至AI国际竞赛（如中美）和Lindy's Law，但缺乏实质性技术分析，更多是对预测本身可靠性的质疑。
- **结论：** AI能力曲线并非简单指数，sigmoid形态下预测准确度极低；需警惕对短期跃升的过度渲染，实际应用应关注任务复杂度上限与不可靠性。

### 1. 我发现 CC 和 Codex 越来越像是温水煮青蛙

- 文章来源平台：V2EX
- 原文链接：<https://www.v2ex.com/t/1213096>

**AI 总结**

- 模型提供商通过修改分词器、提高单次任务额度消耗（如倍数计数），以及降低普通模式速度并推出按倍数消耗额度的 fast 模式，实现变相涨价。
- 短期推出额度翻倍活动来掩盖用户对高消耗的感知，活动结束后用户只会觉得额度“不禁用”而难以直接归因于涨价。
- 评论指出，转为“token 收费”后提供商无动力优化费效比，实际消耗的 token 数量由平台单方决定，甚至使用“代币”虚拟概念，用户无法核实成本。
- 这种策略逐渐恶化用户体验，类似“温水煮青蛙”，且对依赖 API 的开发者、中小企业、高频调用者成本冲击最明显。
- 结论：CC/Codex 等模型平台正通过分步调整计费规则与体验阈值，隐蔽地提高用户实际使用成本，用户需持续监控额度消耗与速度变化。
