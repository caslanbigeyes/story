### 3. Android Clean Architecture 中 Use Case 只能有一个方法吗？

- 文章来源平台：掘金
- 原文链接：<https://juejin.cn/post/7640016020847034420>

**AI 总结**

- Use Case 不必只有一个方法，关键在于业务规则独立、依赖方向清晰、模块边界稳定和复杂性可控。
- 单 invoke 风格流行原因包括强制职责单一、符合 Kotlin 函数式风格和易于组合业务流程。
- 多个方法并非错误，关键在于业务语义相关性和依赖共享。
- 警惕 Use Case 成为 Repository 的透传层，避免机械分层。
- Use Case 应承担业务规则、数据编排、多数据源协调等职责。
- Clean Architecture 目标是解决复杂度失控、依赖混乱、业务耦合和测试困难，而非类模板规范。
- Use Case 是业务边界的表达方式，方法数量和实现方式并非关键。
