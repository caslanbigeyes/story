## 先理解几个概念

### 1. Vibe Coding 是什么？

现在很多人用 Claude Code、Cursor、Codex 写代码：

比如：

你：

> 帮我开发一个用户中心

AI：

* 看代码
* 修改文件
* 跑测试
* 修 bug

这种叫 **vibe coding（凭感觉开发）**。

问题：

小项目很好，大项目容易失控：

* AI 不知道整体架构
* 修改 A 影响 B
* 上下文越来越长
* 做几小时后忘记之前决策

---

# 2. 什么是 Harness？

Harness 可以理解：

> 给 AI Agent 套一个工作流程控制层。

普通 AI：

```
你
 |
Prompt
 |
Claude Code
 |
代码
```

Harness：

```
你
 |
任务
 |
Harness
 |
--------------------------------
| Planner       规划
| Implementer   开发
| Reviewer      审查
| Fixer         修复
| Archive       记录
--------------------------------
 |
Claude/Codex Agent
 |
代码
```

它负责：

* 拆任务
* 调度 Agent
* 保存上下文
* 控制循环
* 自动检查

# 第二阶段：OpenSpec

OpenSpec 是一种：

> 规范驱动开发（Spec Driven Development）

核心思想：

不要直接写代码。

先写规格说明。

比如：

开发登录功能。

先生成：

```
specs/login.md
```

里面：

```md
需求：

用户可以手机号登录


接口：

POST /login


数据库：

user表增加字段xxx


页面：

Login.tsx
```

然后 AI 根据 spec 开发。

流程：

```
需求

↓

propose
生成方案

↓

apply
执行代码

↓

archive
保存记录
```

---

但是问题：

还是需要人操作。

比如：

你执行：

```
/opsx:propose
```

然后：

```
/opsx:apply
```

然后：

```
/opsx:archive
```

作者觉得：

## Rasen 自动流程

一个任务：

比如：

> 开发支付模块

它自动：

### 1. Planner

规划：

```
支付模块拆成：

change1:
支付接口

change2:
订单状态

change3:
支付回调

change4:
前端页面
```

---

### 2. Implementer

开发：

AI 开始写代码。

---

### 3. Reviewer

另一个 AI 检查：

比如：

发现：

```
支付回调没有幂等处理
```

---

### 4. Fix Cycle

自动返回：

开发 AI：

```
修复支付幂等问题
```

然后重新 Review。

---

### 5. Ship

提交：

```
git commit

git push

create PR
```

---

### 6. Archive

保存：

```
这次改动做了什么

为什么这么设计

遇到什么问题
```

---

整个过程：

```
需求

 ↓

Planner

 ↓

Developer

 ↓

Reviewer

 ↓

Bug?

 ↓

Fix

 ↓

提交代码

 ↓

记录知识
```

完全自动。

# Context 上限是什么意思？

LLM 有上下文限制。

比如：

Claude：

200K token

但是：

不是越多越好。

作者说：

模型超过 30%-40% 上下文后效果下降。

例如：

你的项目：

```
100个文件

10万行代码

聊天记录5万字
```

AI：

开始：

记得很好

后来：

```
上下文爆炸
```

AI：

* 忘记设计
* 重复修改
* 产生错误

# Handoff 是什么？

类似：

AI 接力。

比如：

Agent A 工作：

```
已经完成：

用户模块

剩余：

订单模块
```

但是上下文快满。

它生成：

handoff.md

里面：

```
当前状态：

完成用户表设计

修改文件：

User.ts

UserService.ts


下一步：

继续订单开发
```

然后：

启动新的 Agent B。

Agent B：

读取：

handoff.md

继续。

类似：

程序员换人：

```
老员工：
我做到这里，你继续

新人：
好的，我接着做
```
